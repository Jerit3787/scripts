AI Discord Bot

Private Discord bot and monitoring dashboard

Install the bot, dashboard and Watchtower from private GHCR images with one command. The installer keeps .env and data/, generates the dashboard login and starts the Compose stack with Docker.

Read the docs View source

Install

Choose how this server should be set up. Run the same command again to update.

$curl -fsSL https://scripts.danplace.tech/AI-Discord-Bot/setup.sh | bash

Clones or fast-forwards the private app into /opt/ai-discord-bot, asks for the bot settings, generates the dashboard login and starts the stack. Requires GitHub access to the private repository.

Prefer to read it first?

Open setup.sh in the viewer 
$curl -fsSLO https://scripts.danplace.tech/AI-Discord-Bot/setup.sh && less setup.sh && bash setup.sh
$curl -fsSL https://scripts.danplace.tech/AI-Discord-Bot/setup.sh | \
  GITHUB_TOKEN='<repo + read:packages PAT>' \
  GHCR_USER='<your GitHub username>' \
  DISCORD_TOKEN='<bot token>' \
  OPENAI_API_KEY='<OpenAI-compatible key>' \
  TOKEN_MODE=bot DASHBOARD_HOST_IP=100.64.0.10 \
  AI_DISCORD_BOT_NON_INTERACTIVE=1 bash

No prompts. A fresh unattended install needs the Discord token and API key; the dashboard password is generated and printed once. Set GHCR_TOKEN separately if GITHUB_TOKEN does not have read:packages.

$curl -fsSL https://scripts.danplace.tech/AI-Discord-Bot/setup.sh | \
  GITHUB_TOKEN='<repo PAT>' bash

# Or update the images without re-running the installer
discord-bot update

The checkout is fast-forwarded, .env and data/ are kept, the current image is pulled and the containers are recreated. Use --no-git-update when the checkout is managed separately.

The repository and image are private

On a fresh server, give bash a GitHub token (not curl), sign in with gh auth login, or use an SSH key. The image pull needs a PAT with read:packages; GHCR_USER is your GitHub username, the account that owns that token. Tokens are used for the run only and are not written into .git/config.

What the installer sets up

Everything below is configured by the installer. Existing secrets and data are left alone.

Private bootstrap

Clones Jerit3787/ai-discord-bot, logs in to GHCR and pulls the :bot or :user image. No Node or Python runtime is needed on the host for the bot.

Two token modes

Official discord.py bot mode or discord.py-self user mode. The installer keeps TOKEN_MODE and CONTAINER_TAG aligned and warns about the self-bot ToS risk.

Dashboard login

Generates a scrypt password hash, signed HttpOnly cookie session secret and CSRF-protected login. The password is printed once and never stored in plaintext.

One-click updates

Watchtower watches only the labeled bot container, pulls the private image and removes superseded images. The dashboard's Update bot button calls it with a generated token.

Data-safe re-runs

Every run preserves .env, data/, the database and the dashboard login. The previous environment is saved as .env.bak before a write.

Host controls

Detects the Docker socket group and config path for the dashboard Logs tab, service controls and Watchtower. Links the discord-bot command when possible.

Wizard walkthrough

The questions a fresh interactive install asks.

  1. Where should it live?

    Default /opt/ai-discord-bot on Linux. Existing checkouts are reused.

  2. Which Discord token mode?

    • bot — supported, ToS-safe
    • user — self-bot, ban risk

  3. Where should the dashboard listen?

    A Tailscale or private LAN IPv4 address, or 127.0.0.1 for local-only access.

  4. OpenAI-compatible endpoint and Discord token

    The API key, base URL, model and the matching bot or user token. Secrets are hidden.

  5. Dashboard password

    Enter one, or press Enter to generate a random password. The generated value is printed once.

  6. Pull and start

    Logs in to GHCR, pulls the image, starts the bot, dashboard and Watchtower, then prints the URL and login.

Security notes

Kept private

  • Tokens and the dashboard password hash stay in .env with mode 600.
  • GHCR credentials live in the installing user's ~/.docker/config.json.
  • The dashboard binds to a single private interface unless you choose otherwise.
  • Existing data/, the SQLite database and .env survive updates.

Watch out

  • TOKEN_MODE=user is a self-bot and can get the Discord account banned.
  • DASHBOARD_HOST_IP=0.0.0.0 exposes the dashboard on every interface.
  • The dashboard mounts the Docker socket; keep its login strong.
  • Watchtower updates only the bot container. Update the dashboard with the installer or discord-bot update.

Before you start

  • Linux server

    Docker Engine with Compose v2. macOS works with Docker Desktop; Linux is the primary target.

  • GitHub access

    A token, gh auth login, or an SSH key for the private repository, plus a PAT with read:packages for GHCR.

  • A private address

    Tailscale or a private LAN address for the dashboard. 127.0.0.1 keeps it local.
