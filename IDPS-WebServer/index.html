CAIDPS

Context-Aware Intrusion Detection & Prevention System

Install CAIDPS with one command. The setup wizard picks a run mode, the app to protect and an optional Cloudflare Tunnel, then starts the live SOC dashboard with ML detection and behavioral profiling.

Read the docs View source

Install

Choose how this server should be set up. Run the same command again to update.

$curl -fsSL https://scripts.danplace.tech/IDPS-WebServer/setup.sh | bash

Clones or fast-forwards the app into /opt/caidps, installs Git, Git LFS and Python, then runs the setup wizard in your terminal.

Prefer to read it first?

Open setup.sh in the viewer 
$curl -fsSLO https://scripts.danplace.tech/IDPS-WebServer/setup.sh && less setup.sh && bash setup.sh
$curl -fsSL https://scripts.danplace.tech/IDPS-WebServer/setup.sh | CAIDPS_NON_INTERACTIVE=1 bash

The recommended setup for servers: the production Docker Compose stack (PostgreSQL, Redis, backend, proxy and Juice Shop) with no prompts. It installs the caidps-hostd updater and the nightly backup timer, then prints the one-time setup code. To change the upstream, add HTTPS or restore a backup, see installer flags.

$curl -fsSL https://scripts.danplace.tech/IDPS-WebServer/install-image.sh | \
  CAIDPS_GHCR_TOKEN='<classic PAT with read:packages>' \
  CAIDPS_GHCR_USER=Jerit3787 \
  bash -s -- --non-interactive --profile production --run containers

For a production server that shouldn't keep a git checkout, LFS weights, submodules or a backend venv. It pulls the released app image and its host bundle, and dashboard updates then pull new images instead of building. Replace the token placeholder before running.

This deletes local CAIDPS data

The checkout is deleted too, including its backups/ folder and deploy/.env. Run scripts/backup.sh create and copy the archive off the server first.

$curl -fsSL https://scripts.danplace.tech/IDPS-WebServer/reset.sh | bash

You'll be asked to type reset. It removes every CAIDPS install it finds, so stop any install you want to keep before running it.

Removed

  • The Compose stack with its named volumes: the database and Redis and Caddy data
  • caidps-hostd, caidps.service and the backup timer
  • The checkout, the caidps command and host-managed tunnel credentials
  • The local caidps PostgreSQL database and role, on systemd installs

Left in place

  • External PostgreSQL and Redis
  • Dashboard and token-managed Cloudflare tunnels
  • Unrelated Docker workloads
  • Docker images and packages, unless you pass --purge-packages

The app repository is private

On a fresh server, give bash a GitHub token (not curl), sign in with gh auth login, or use the wizard's PAT or SSH prompt. The token is used for that run only and isn't written into .git/config.

What the wizard sets up

Everything below is configured by the installer. Nothing needs to be prepared by hand.

Bootstrap

Clones Jerit3787/IDPS-WebServer on fyp2-real-detection, installs Git LFS and Python with venv, and pulls the released container image, building locally only when no image is available.

Install modes

The default Docker Compose stack protects Juice Shop in the stack or an existing upstream. A systemd install can also target VulnBank, MediVault, DVNA and CI/CD Goat.

Multi-tier detection

The inline reverse proxy on :8081 inspects traffic with the rule engine, a DistilBERT transformer, behavioral profiles and threat-intelligence reputation.

Cloudflare Tunnel and HTTPS

Container installs use a Zero Trust tunnel token or a Cloudflare Login named tunnel. Host installs can also use Quick Tunnels (*.trycloudflare.com). Caddy serves HTTPS when there's no tunnel.

Live SOC dashboard

Incident management, a MITRE ATT&CK heatmap, a request inspector and automated IP mitigation at http://localhost:8000.

Updates and backups

Container installs get the caidps-hostd updater, so you can update from the dashboard, and a nightly backup timer. systemd installs get the caidps service and the same 03:17 backup timer.

Reference

Pass flags after bash -s --, and environment variables before bash.

FlagEffect
--non-interactive --profile production --run containersThe unattended production stack. Same as CAIDPS_NON_INTERACTIVE=1.
--upstream URLProtect an app that's already running instead of Juice Shop in the stack.
--project NAMECompose project for a second install on the same machine.
--tls acme --dashboard-domain HOST --acme-email EMAILHTTPS in the stack with Let's Encrypt. Your own certificate files or Caddy's internal CA also work.
--restore PATHRestore a scripts/backup.sh create archive into a new stack.
--run systemd --install-localsystemd service with PostgreSQL and Redis installed on this server.
--postgres-url URL --redis-url URLsystemd service using an existing PostgreSQL and Redis.
--local-buildBuild the app image here instead of pulling the release.
--dry-runPrint the resolved configuration and commands. It may still clone or fast-forward the checkout.
VariableEffect
GITHUB_TOKEN, GH_TOKENToken for the private clone or update, for this run only.
CAIDPS_NON_INTERACTIVE=1Skip prompts and install the production container stack. CI=1 does the same.
CAIDPS_INSTALL_DIRInstall path. Default /opt/caidps on Linux.
CAIDPS_BRANCHBranch to install. Default fyp2-real-detection.
CAIDPS_TUNNEL_TOKENCloudflare Tunnel token for a container install.
CAIDPS_GHCR_TOKENPAT with read:packages to pull the private app image. Without it, a failed pull builds locally.
CAIDPS_GHCR_USERGitHub account for the token. Default: the gh CLI's account.
CAIDPS_NODE_CHANNELNodeSource channel for systemd prerequisites. Default lts.
OptionEffect
--yesNo prompt. Required when there's no terminal. CAIDPS_RESET_CONFIRM=yes does the same.
--purge-packagesAlso uninstall cloudflared, Node.js, Docker and whiptail, and delete all Docker images, containers and volumes on the machine.
--dir PATHAlso remove an install outside the default locations.
--project NAMECompose project to use when deploy/.env is missing or unreadable.
--kind containers|systemdForce the install kind when its metadata is missing.

Every option, with examples, is in the README.

Before you start

  • A Linux server

    Docker Compose or systemd. Reset relies on /proc, so macOS isn't supported.

  • sudo or root

    Package and service steps use sudo. Without a terminal, run as root or with passwordless sudo.

  • GitHub access

    A token, gh auth login, or an SSH key for the private app repository.
